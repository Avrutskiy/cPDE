# Code provenance and AI-use disclosure

cPDE 0.2.0 combines a supplied numerical core with substantial AI-assisted
implementation, debugging, testing and documentation using OpenAI Codex. In the
informal sense, much of the surrounding software was "vibecoded" under the project
owner's direction. The whole repository should not be described as either wholly
AI-generated or wholly written without AI.

## Pre-existing numerical code

The starting point was the supplied `cpde_fourier_experiment_bundle_v3.zip`.
The network's sigmoid derivative formulas, explicit high-order and mixed
spatial-derivative propagation, and corresponding weight backpropagation came
from that numerical code. They were not newly generated by Codex in this work.
The retained implementations are primarily in `cuda/derivative_kernels_v4.cu`
and the numerical portions of `cuda/cpde_engine.cuh`, including the separate
`d4`/`d4p`, `d5`/`d5p` and `d6`/`d6p` functions.

The matrix/network infrastructure and optimizer update kernels also derive from
the supplied implementation. Those parts have since received AI-assisted edits;
"pre-existing" does not mean that the complete files are unchanged.

This attribution describes the boundary of the recorded development work. It
does not certify how every line of the earlier supplied archive was originally
written; a complete earlier authorship history is not included in this repository.

## AI-assisted additions and modifications

| Area | AI involvement in this release |
|---|---|
| Python package, `cpde/` | Substantial implementation of sessions and transport, data/network/state interfaces, wrapper weight initialization, validation, derivative-schema preparation, expression parsing, cost composition and quadrature. |
| Persistent server, `cuda/cpde_server.cu` and `cuda/protocol.hpp` | Implementation of the command protocol, object lifetime, execution scheduling, training/reporting, diagnostics and state transfer around the retained engine. |
| Costs, expressions, graphs and reductions | Implementation of `cost_kernels.cuh`, `reduction_kernels.cuh`, `cost_graph.cuh`, `expression_program.hpp`, `graph_schedule.hpp` and `scalar_ops.cuh`, including NVRTC generation and scalar-expression differentiation. |
| Existing engine | Audit-driven fixes and cleanup: ownership, bounds/state checks, shared metadata, value-only storage, gradient-history handling, constant fills, removal of unused interfaces, and CPU/CUDA launch dispatch. Existing optimizer and derivative formulas were not generally replaced. |
| Production CPU backend, `cpu/` | New host-memory, BLAS and reduction adapters and build targets; integration of the expression interpreter. The CPU backend reuses the supplied numerical formulas through shared sources. |
| Examples and validation | Substantial writing and revision of example scripts, geometry/cost setup, analytical and finite-difference checks, test adapters, integration tests, numerical audits, performance benchmark harnesses, result collection and plotting tools. Scientific objectives and requested changes were directed by the project owner. |
| Build and release tooling | CMake integration, macOS/Linux/Windows scripts, CI configuration, packaging and checksum/manifests. |
| Documentation and figures | README/API walkthroughs, equations and explanations, disclosure/release documents, and plotting code/formatting. Result figures plot recorded numerical runs; they are not AI-generated illustrations. |

The project owner supplied the starting implementation, set the requirements,
and accepted or rejected proposed changes. Deferred derivative/optimizer formula
changes remain deferred; the approved legacy repair patch is retained without
restoring the removed interface. See [known issues](KNOWN_ISSUES.md).

## What was checked

AI-assisted code was exercised with native CPU and CUDA builds, unit/integration
tests, analytical and finite-difference comparisons, independent high-order
reference calculations, and example runs. Test and reference code itself also
received AI assistance; it is not presented as a separate human audit.

Actual environments, coverage and untested platforms are listed in
[VALIDATION.md](VALIDATION.md). Passing those checks does not establish that all
formulas, edge cases or scientific conclusions are correct.
